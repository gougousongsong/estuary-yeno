# YeNo verification procedure for reuse

1. Read the current public evaluator contract and starter instructions before designing strategy. HouseBot benchmark is diagnostic, not qualification.
2. Retain fixture source URLs and SHA256; compare downloaded bytes to local files. If no redistribution license is supplied, keep organizer fixtures out of the independent submission archive and provide pinned fetching.
3. Use evaluator-owned account state. Validate both directions of reference age (future and stale); target provisional/future rows cannot drive entries.
4. Walk asks ascending and bids descending, charge both documented fee components, include prior partial-sale proceeds, honor minimum size, fee-inclusive cap, bid depth and adverse execution cushion on each side.
5. Test risk-reducing SELL with bids only and insufficient depth; a full-depth precondition can strand inventory.
6. Start a temporary loopback HTTP server, execute the unmodified official smoke test, measure endpoint responses, reject malformed requests, and shut down/join the server.
7. Report handcrafted scenarios strictly as boundary tests. No replay/historical/OOS/official score exists without organizer-supplied data and evaluator output.
8. Hand the parent source, README, verification output and hashed archive. Parent owns contact, immutable publication identity and final submission.
